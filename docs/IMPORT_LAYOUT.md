# 目录确认导入

不同 Pod、服务不需要统一打包目录。上传或在线采集后，LogScope 先显示 ZIP 中的真实目录和样例，确认后再建立全文索引。目录判断使用本机规则，不调用 AI，也不消耗模型额度。

## 操作步骤

1. 点击“导入日志包”上传 ZIP，或完成“在线采集”。程序保留原包，开始扫描目录。
2. 打开目录确认窗口，查看归档链、实际目录、文件清单、内容样例及识别置信度。默认选中常见的文本日志；没有自动选中的目录也可以手动勾选。
3. 修改不准确的 Node、命名空间、Pod、服务和日志类型。不能确定的字段可以留空；日志类型留空时按各文件名判断。分类修改不会改变或覆盖真实文件路径。
4. 选择需要导入的目录，并设置该目录的文件名匹配。例如 `*.log,*.log.gz`、`access*`、`*.txt,*.out`、`*.abc` 或 `stdout`。多个规则用逗号分隔，匹配文件名、不包含目录；可用 `*` 查看匹配全部文件的效果，但匹配到二进制或损坏文件时需缩小范围。
5. 选择日志分行方式，检查样例。若需要更改编码，选择新编码后点击“重新扫描”，再次核对识别结果和目录归属。如果当前不准备导入，点击“保存草稿”；刷新页面或重启服务后仍可继续。
6. 点击“确认并建立索引”。确认前没有可搜索的日志记录；导入完成后自动切换到该日志包。

目录按包含实际文件的位置分组，子目录单独显示。可以搜索目录、分组选择，文件清单和样例按需展开，避免一次展开大量文件。修改目录范围是选择压缩包里真实存在的其他目录，不需要重命名 ZIP 内文件。

## 识别与解析的边界

| 内容 | 行为 |
|---|---|
| 原有 `namespace_pod/service/pod-service/log/` | 交叉验证名称一致性，作为高置信度规则 |
| `logs/`、任意服务路径、ZIP 根目录 | 根据名称给出可编辑推测，不能确定的字段留空 |
| `.log`、轮转日志、`.txt`、`.out`、`.jsonl`、`stdout` 等 | 检查少量文本样例后默认选择候选日志 |
| 非常见扩展名或无扩展名 | 展示目录和文件，可手动设置匹配并勾选 |
| GZIP 日志 | 在 ZIP 中流式解压读取，保留完整来源 |
| 已识别的时间、access、root 日志头 | 继续解析时间、接口、状态码、线程或流水号 |
| 未识别的文本格式 | 保留原文供关键词搜索；不保证提取时间、流水号等字段 |
| 二进制、损坏压缩日志、加密 ZIP、7z、rar、tar | 不作为文本日志导入，显示对应提示 |

“自动合并”使用已识别的时间开头划分记录，并把后续 Java 堆栈等续行合并。没有识别出时间开头的文本按行保存，避免把整份文件合成一条超大记录。对于 JSON Lines、每行独立消息等，也可以明确选择“每行一条”。

时间筛选只包含识别出时间的记录。修改目录和类型不会自动增加一种新的字段解析器；未知字段格式需要后续按样例扩展。目录确认阶段展示的是有界样例，不代表已验证文件全部内容，后段损坏可能仍在导入时暴露。

## 保存、失败重试与原包

- 原 ZIP：`data/archives/<日志包ID>.zip`。
- 方案和草稿：`data/import-plans/<日志包ID>.json`。
- 已导入索引：仍位于 `data/logs.sqlite3`。

关闭确认窗口不会开始导入或删除 ZIP。已保存的草稿跟随该日志包；两个页面同时修改时，旧版本保存或重复确认会提示重载，避免互相覆盖。

扫描或导入失败后，新流程暂留原 ZIP，供保留期内重试。规则有误可以修改后重新确认，扫描中断或计划损坏可以“重新扫描”。重新扫描会重新生成识别结果，应再次检查分类和文件匹配。进程中断留下的部分索引会在重试前清理，不重复累加日志。

不需要的待确认或失败任务，可在首页“导入任务”对应行点击 **取消导入**，也可在确认窗口底部点击同名按钮。确认后会删除这次上传到服务电脑的 ZIP、方案、浏览器本地草稿和该包的残留索引，不影响其他日志包或你电脑上原先选择的 ZIP 文件。取消过程中会显示“正在取消”，完成后任务从列表消失，刷新不会恢复；请求失败会保留任务并允许重试。关闭确认窗口仅暂存任务，不等于取消。扫描或索引进行中仍需等待结束；若其他页面已经确认或完成导入，取消会提示刷新，不会直接删除已完成的日志包。v2.5 每天 02:00 对满 72 小时的日志包同时清理 ZIP、索引和方案；成功导入从完成时间计时，待确认或失败包从创建时间计时。需要长期保存的原包应先下载，详情见 [清理说明](RETENTION.md)。

## 性能与限制

扫描读取 ZIP 目录和少量文件前缀，不遍历日志全文做解析/索引。嵌套 ZIP 仍需流式写入临时文件才能读取内部目录，因此大型嵌套包扫描并非零 I/O。确认导入会读取选中的日志全文。

默认限制为最多 4 层嵌套、100000 条目、5000 个含文件目录、24 MB 预览清单；样例总量最多 1 MB，最多每目录 3 份样例。超限会明确报错并建议分批，不静默遗漏成员。展开内容还受 `LOG_MAX_EXPANDED_GB`（默认 20 GB）与日志记录大小限制约束。

升级先关闭旧进程再替换 EXE/更新源码，完整保留 `data`。已有可搜索日志无需重新建立索引。此前因旧目录限制而失败、且旧版未保留 ZIP 的包，升级后需要重新上传一次。
