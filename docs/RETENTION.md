# 日志保留与自动清理

LogScope v2.5 默认在程序运行期间到达服务电脑本地时间 **02:00** 时，删除满 **72 小时**的日志包原始 ZIP、日志记录和检索索引。上传和在线采集的日志包使用同一策略。**默认不启动补扫，错过等下一次 02:00，不在白天自动重试。** AI 历史、配置及 `data/projects/` 代码仓库保留。

本策略替代旧版“只删索引、永久保留 ZIP”。升级后，已启用的自动清理直接使用新策略，不再逐包询问；需要长期留存的日志，请在过期前下载到自行管理的目录。

## 怎么算过期

- 新导入的日志包，从**导入完成时间**算起，达到 **72 小时**后进入下一次定时清理的候选范围。
- 不使用日志内的业务事件时间；上传去年的日志，也有从本次导入完成开始的 72 小时。
- 旧版已清理索引但保留 ZIP 的包，仍使用原导入完成时间；没有该时间时回退使用原创建时间。升级不会重新开始计时。
- 待确认、失败或中断导入尚未成功完成的包，按原创建时间计算；超过 72 小时后，其原 ZIP、导入方案及残留索引也会清理。
- 72 小时是过期门槛，不是精确删除时刻。每日统一检查一次，因此实际保留时间通常为 72～96 小时；运行中的任务、停机和清理重试可能进一步延后。

例如周一上午 10:00 导入完成，周四上午 10:00 满 72 小时；如果期间服务一直运行且没有任务阻碍，将在周五凌晨 02:00 清理。

## 哪些保留，哪些清理

| 内容 | 自动清理行为 |
|---|---|
| 过期日志包的日志记录、文件解析元数据、全文检索索引 | 清理 |
| 过期的上传或在线采集原始 ZIP，以及对应导入方案 | 删除 `archives/<日志包ID>.zip` 和 `import-plans/<日志包ID>.json` |
| 创建时间超过 72 小时的待确认包或失败导入残留 | 清理，包括原 ZIP、导入方案和残留索引 |
| 未过期日志包及其原 ZIP、索引 | 保留，正常使用 |
| 旧版仅删索引后留下的原 ZIP | 按原导入完成时间或创建时间判定，过期后删除 |
| 日志包名称和清理状态等元数据 | 可继续用于说明清理结果，不等于原文件仍存在 |
| 原生 AI 对话、报告、磁盘上的旧终端历史文件 | 保留；不恢复旧终端功能 |
| `data/projects/` 中的代码仓库缓存 | 保留；不受日志包清理影响 |
| 模型 API 配置、采集环境、分析规则 | 保留 |

`logs.sqlite3` 是共享数据库容器，不会直接删除整个数据库文件。程序会删除过期日志包对应的记录与索引，然后执行数据库物理压缩（SQLite `VACUUM`）回收空闲页，因此 `data` 中依然会有数据库文件。未过期日志、归档清单等仍需要它。

原 ZIP 管理范围是 LogScope 数据目录中的 `archives/`。在线采集成功后移入这里的 ZIP 同样清理；不会扫描用户采集脚本的任意输出目录，也不会删除浏览器下载目录或电脑上无关的 ZIP。原本缺失或已经删除的 ZIP 不提供可用下载入口。

这是**释放磁盘空间**的功能，不是直接清空程序内存，也不会因为某个日志包到期就关闭 AI 会话。

## 调度、停机与正在使用的任务

时间以**运行 LogScope 的服务电脑**为准，不是同事浏览器所在电脑的时区。左侧状态显示下次检查时间及其 UTC 偏移，悬停可查看服务时区。

- 程序运行时，在每天本地时间 02:00 自动检查。
- 程序关闭时不能清理；默认错过后不会在下次启动补跑，而是等下一次 02:00。因此只在白天开机的服务不会自动清理，若需每天清理应保持服务夜间运行。
- 当前有导入、查询或 AI 排查任务时，不打断这些任务；仅在 **02:00～03:00** 夜间窗口内，每 **15 分钟**重试。窗口结束后等下一次 02:00，不持续在白天重试。
- 页面以实际数据库占用状态判定能否搜索。正在排队、检查或请求停止，并不一定占用数据库；只有后端实际维护期间才暂停查询。
- 清理时约每 **2 秒**更新阶段，空闲时约每 **30 秒**检查计划；结束后刷新日志包列表并清掉失效结果。首次打开页面遇到维护，也会恢复你的视图、筛选和草稿，自动重试加载。
- 状态接口短时不可用时会提示“维护状态待确认”，不会让过期的前端标记永久禁止搜索；你可以重试搜索，后端若仍在维护会返回明确提示，保护数据库。

压缩数据库需要一定临时磁盘空间。请不要等磁盘完全写满才处理。除了正在运行的任务，磁盘余量不足、数据库忙或压缩失败也可能导致延期；页面会显示具体原因与下次检查时间。重试仍受夜间窗口限制。不要在运行中手动删除 `logs.sqlite3` 或其伴随文件。

## 进度与停止

页面显示后端实际执行阶段，例如检查过期日志、删除过期索引和原 ZIP、写回 WAL、合并全文索引、压缩数据库和完成维护，同时显示总耗时、已处理日志包数及当前对象。

SQLite 的单条删除、索引合并和 `VACUUM` 没有可信的完成百分比，因此阶段内使用**不确定进度条**，不会把“正在压缩”编造成某个百分比。已处理包数也不代表整个数据库压缩的百分比。

需要结束维护时点击 **停止本次清理**。界面先显示“正在安全停止”，由后端发出 SQL 中断请求并等待事务收尾或回滚，确认维护结束后再恢复正常状态。**取消不是立即强杀，也不能保证毫秒内完成**；磁盘慢、事务较大时，安全回滚仍可能耗时。

停止不撤销此前已经提交的数据库删除，也不能找回已经删除的 ZIP。未提交的数据库事务会安全收尾或回滚；页面最终显示本轮实际清理结果。部分文件因占用或中断尚未删除时会保留失败提示，后续清理可重试；不要把“停止”理解为恢复已删除的数据。

## 可选本地配置

首次启动会在数据目录生成 `retention-config.json`，默认如下；使用 `--data` 时位于该指定目录。配置只由维护者本地编辑，修改后重启 LogScope 生效。

```json
{
  "enabled": true,
  "startup_catchup": false,
  "max_run_seconds": 300
}
```

- `enabled`：是否启用自动清理；设为 `false` 可关闭后续定时清理。
- `startup_catchup`：是否主动启用启动补扫。默认 `false`，建议保持不变；设为 `true` 后可能在白天启动时补删过期 ZIP 和索引，这是维护者显式选择的额外行为。
- `max_run_seconds`：单轮清理的运行预算，默认 300 秒，可配置 1～3600 秒。达到预算时请求安全停止；**不是硬截止时间**，SQL 响应中断及事务回滚可能继续花时间。

不需要配置 Windows 任务计划；调度跟随 LogScope 服务运行。配置损坏时页面会提示具体错误，不会擅自采用更激进的启动清理方式。

## 查看、下载或手动删除 ZIP

1. 点击左侧 **查看保留 ZIP**。
2. 根据原日志包名称找到尚在磁盘上的归档，查看大小和相对路径；列表中有历史清理信息不代表 ZIP 永久保留。
3. 需要保存时点击 **下载原始 ZIP**，文件会下载到当前使用浏览器的电脑。
4. 不需要的保留 ZIP 可在列表中手动删除，确认后释放对应原包空间。此操作不会删除 AI 对话、配置或代码仓库。

也可以在服务电脑直接找到 `data/archives/<日志包ID>.zip` 再上传；如果用了 `--data`，则路径相对于你指定的数据目录。页面显示的原始名称和磁盘上的 ID 文件名不同，这是正常的。

## 清理后还想分析

**自动清理正常完成后，原 ZIP 也已删除。** 需要再次分析时，使用自己保存的 ZIP 重新上传，或者重新在线采集。重新导入、确认目录并完成索引后，新日志包获得新的 72 小时保留期。

旧 AI 会话仍能回看之前的文字、报告和已保存的工具结果，但是被清理的索引已不存在，**旧证据的日志详情、重新查询与继续基于旧日志的排查不可用**。重新导入会生成新日志包 ID，不会偷偷改变旧会话的证据范围，建议对新日志包新建排查。

## 和手动删除的区别

**自动清理按时间删除过期 ZIP 和索引；手动操作由用户立即指定对象。**

左侧 **删除当前日志包** 删除该包的原 ZIP、日志记录、索引和导入方案，不用等满 72 小时。保留 ZIP 列表中的删除用于清理已没有可用索引的归档。两种操作均不删除 AI 历史、配置或 `data/projects/`。

## 升级需要重新导入吗

**未被清理的日志不需要事先重新导入。** 先关闭旧 LogScope 服务，再替换 EXE 或更新源码，继续使用原来的 `data` 目录即可。完整保留 `logs.sqlite3`、`logs.sqlite3-wal`、`logs.sqlite3-shm` 等数据库及其伴随文件；不要只复制数据库主文件，也不要在维护期间手动删文件。升级不会重建全部索引。

新版本默认不会一开机就清理，即使旧版本留下白天的重试状态，也等下一次凌晨 02:00。旧数据继续按原导入完成时间、缺失时按原创建时间判断，不因升级重新计时。下一次清理开始使用 ZIP 与索引一起删除的新策略，包括旧版留下的过期原包。

**已经提交的过期删除，不能靠升级自动恢复。** 原 ZIP 尚存时可先下载留存；原包已删除或未留存时，需使用自行保存的文件或重新采集。原生 AI、模型配置、采集环境和项目代码缓存继续保留。旧终端历史也留在磁盘，但 v2.4 已移除旧终端页面与 API，详见 [升级与保存位置](NATIVE_AI.md#保存位置和升级)。
