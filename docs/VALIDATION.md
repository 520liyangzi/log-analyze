## v1.4 时间粘贴、页面恢复与日志包删除

新增删除集成测试：同时导入两个日志包，运行中的 AI 终端会阻止删除；结束终端后删除目标包，确认原始 ZIP、logs、files 和 FTS 索引均被移除，另一个日志包仍能正常查询。删除后执行 WAL 截断和数据库压缩；压缩因临时空间不足失败时，删除的页面仍可被后续导入复用。

时间筛选回归测试覆盖直接复制的 `2026-09-08 09:55:14.000`（无时区）并按默认 `+0800` 正确查询。前端改为文本时间框，完成 JavaScript 语法、HTML 控件与新增静态样式入口检查。搜索表单、日志包、页面、流水号和 AI 问题通过浏览器 localStorage 恢复，不保存日志搜索结果正文。

## v1.5 任务确认与代码定位

任务预览现在包含日志包范围和从问题提取的接口/流水号线索，页面只有在用户确认预览后才启动 AI。接口路径查询使用部分 URL 索引，演示数据的查询计划确认命中 `logs_url`，不再用 `substr` 扫描全部日志记录。

代码定位集成测试创建临时 Git 仓库，验证项目根目录/分支识别、`code-task.md` 预览与落盘一致、只读 `grep` 能读取固定提交，以及分支在预览后移动会阻止发送旧任务。日志报告不存在、终端已结束或目录不是 Git 仓库时均拒绝进入第二阶段。

## v1.6 多排查窗口与会话恢复

新增集成测试使用确定性本地程序代替公司 AI，验证终端输出写入 `terminal.log`、任务元数据与 UUID Session ID 持久化、重新创建终端管理器后仍能枚举历史任务，以及恢复命令严格收到 `--sessions <UUID>`。非法 Session ID 被拒绝。全套共 32 项测试通过。

页面增加运行中/历史排查窗口、历史终端回放、Session ID 手动保存和恢复按钮，并完成 JavaScript 语法与控件引用检查。没有连接真实公司 AI，因此其 `--sessions` 行为仍需在用户环境验证；测试只证明 LogScope 的命令组装、PTY 传输和持久化链路。

## v1.7 排查会话删除

同一集成链路新增删除验证：运行中的排查会话拒绝删除；结束后删除任务目录，任务列表不再返回该会话，历史接口也无法访问。删除只针对所选 `data/terminal-sessions/<ID>`，不影响日志包和其他任务。

## v1.8 日志与代码联合排查

AI 启动前可以选择项目目录和分支。集成测试验证任务预览包含固定 commit 与按需查代码规则，确认启动后生成 `code-task.json`，任务目录中的只读代码工具能读取该固定版本。原有报告生成后的第二阶段入口继续保留。

## v1.9 精简 AI 入口与历史输出

删除一次性的 API 问诊页面、模型配置入口、后端模型调用接口及对应测试，只保留可持续追问、可调用日志与代码工具的本机 AI 排查。历史窗口选择与终端回放分离：选择任务时不请求或显示旧输出，用户明确点击“查看终端记录”后才读取保存内容；恢复按钮仍负责启动真实 AI 会话。

## v1.10 可退出的终端记录回放

“查看终端记录”改为可切换状态：载入后按钮显示“隐藏终端记录”，再次点击会清空回放并返回历史任务概览。切换历史任务、恢复 AI 对话，以及刷新后恢复上次选中的已结束任务时，均不会继续显示旧 CMD 输出。

## v1.11 恢复入口状态修正

历史任务没有已保存 Session ID 时不再禁用恢复入口。用户可以点击获得明确提示，或粘贴 UUID 后直接恢复；只有实际恢复请求期间才显示等待光标和“正在恢复…”。普通禁用按钮使用禁止光标，避免被误认为后台一直处理中。
