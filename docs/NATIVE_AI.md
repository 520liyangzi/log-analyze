# 原生 AI 对话排查

不需要启动 Claude、codeagent、CMD 或安装 Skill。LogScope 后端通过模型 API 的工具调用，执行本机日志索引查询、原包核验和固定 Git commit 的代码搜索；浏览器显示对话和可展开的查询证据。v2.4 已移除旧网页终端及其 API，页面统一使用原生对话。

## 维护者配置模型

1. 首次启动 `LogScope.exe` 或 `python app.py` 后，自动生成 `data/ai-config.json`。使用 `--data` 时就在指定的数据目录中。
2. 用文本编辑器打开 JSON，填写下面三个值，不要把真实密钥提交到 Git，也不要发给同事。

```json
{
  "provider": "openai",
  "base_url": "https://your-model-gateway.example/v1",
  "api_key": "你的密钥",
  "model": "接口要求的模型名"
}
```

其他字段可保留自动生成的默认值；完整示例见根目录 `ai-config.example.json`。JSON 不支持注释。兼容字段 `default_project_path` 可以保留，但 v2.5 页面使用 Git URL 和已导入仓库，不再使用这个默认路径。

3. 保存文件。页面点击“刷新状态”，下一次发送使用新配置，不需重启；已运行的一轮仍使用启动时的配置。“共享模型已配置（仅本地校验，连接在发送时验证）”表示本机配置校验通过，尚未验证网络、鉴权或模型能力；刷新状态不调用模型。
4. 导入演示日志包，问“请检查 /api/model/map 的报错原因”，确认出现“搜索日志索引”等工具记录，再得到回答。

模型状态接口返回是否已配置及提示文字，不返回模型地址或密钥，不提供浏览器编辑入口。所有同事共用维护者配置的模型额度，当前无账号和会话隔离。

### 支持的接口

- `provider: "openai"`：OpenAI-compatible Chat Completions。`base_url` 填含 `/v1` 的前缀，程序追加 `/chat/completions`；也支持直接填写完整 `/chat/completions` 地址。使用 `Authorization: Bearer ...`。
- `provider: "anthropic"`：Anthropic Messages 格式。前缀含 `/v1`，程序追加 `/messages`；使用 `x-api-key`。不能仅因模型叫 Claude 就选此项，应以网关真实协议为准。
- 默认 `stream: true`，模型分段输出时页面持续更新。公司网关不支持流式时改成 `false`，界面保留等待状态，收到完整回复后展示。
- `openai_token_parameter` 默认 `max_tokens`。如网关/模型要求 `max_completion_tokens`，将该字段改成此值。
- 排查模型需支持结构化 `tools/tool_calls`（或 Anthropic `tool_use`）。网关拒绝该能力时会报错；若模型只回复文字而未调用工具，页面会明确提示“未新增工具查询”，不能将文字回复视为实际核查。
- 这是直接 HTTP(S) 连接，当前不自动读取系统代理，也不支持其他厂商的专有鉴权/Responses 协议。企业自签证书需在服务电脑安装信任链，不通过关闭 TLS 校验解决。
- 不使用 CLI 登录凭据，也不会自动从 Claude / 公司 Agent 提取 Key。

### 内网 HTTP、代理与配置排查

支持带端口的内网 HTTP 地址，例如 `http://192.168.10.20:8000/v1`，不要求 HTTPS，也不要求域名。填写的是网关实际前缀；OpenAI 兼容接口会追加 `/chat/completions`，若平台的前缀并非 `/v1`，按平台提供的路径填写，不要机械添加。

模型请求由运行 LogScope 的服务电脑直接发出。当前不读取 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 或 `NO_PROXY`，也没有模型代理配置；修改这些环境变量不会改变此请求的连接路径。若内部网关只能经指定代理访问，需要另外支持代理，不能仅设置环境变量。页面访问正常并不代表服务电脑能连到模型地址。

配置错误发生在连接模型之前，应先按提示检查本机文件：

- JSON 使用 UTF-8，可带 BOM；必须使用英文双引号，不能写注释或尾随逗号。语法错误会给出行、列位置。
- `provider` 只能是 `openai` 或 `anthropic`；平台兼容 OpenAI 时填写 `openai`，不要填写模型名或 `openai-compatible`。
- `stream` 必须是 JSON 布尔值 `true` / `false`；预算字段必须是整数，不加引号，允许范围见下表。
- 若保留旧 `default_project_path`，Windows 路径用 `D:/project/mate/FMEMateService`，或将每个反斜杠写成 `\\`；即使新页面不使用它，JSON 本身仍须语法正确。
- `base_url` 首尾空格会自动忽略；中间不能有空白，端口须为 1～65535。地址里不要嵌入账号、密码、查询参数或 `#` 片段。

提示只标出字段名、类型或范围，不显示配置值。校验通过后，发送一条排查问题来验证实际连接：

| 提示 | 优先检查 |
|---|---|
| 域名解析失败 | 服务电脑是否能解析内网域名，是否已连接公司网络 |
| 连接超时 / 连接被拒绝 | IP、端口、网络路由，以及网关进程是否监听 |
| TLS / 证书错误 | 使用 HTTP 还是 HTTPS、证书信任链与主机名 |
| HTTP 401 / 403 | API Key、接口鉴权协议及模型权限 |
| HTTP 404 | 实际 API 路径和 provider 是否匹配 |
| HTTP 407 | 当前连接的网关是否要求代理鉴权；请求本身没有读取系统代理 |
| HTTP 429 / 5xx | 模型额度、限流或网关服务状态 |
| 响应格式错误 | 网关是否返回所选协议的模型 JSON / 流，而非登录页或其他页面 |

界面不回显服务端返回的原始错误正文。定位时可以提供这类安全提示和 HTTP 状态码，无需发送整个配置文件或 API Key。

### 已配置，但排查提示返回格式不兼容

v2.5.2 修复了兼容网关在流式帧中返回 `tool_calls: null`、`delta: null` 等可选空字段时中断的问题，并补充 SSE 事件解析兼容。旧版的笼统提示不能确定具体原因，也不代表密钥一定错误。

新版错误带有固定诊断码，方便维护者判断：

| 诊断码 | 含义与处理 |
|---|---|
| `response_html` | 接口返回了 HTML 页面；检查是否填成网页入口，或网关是否跳到登录页 |
| `response_json` / `stream_json` | 完整响应或流式事件不是有效 JSON；检查网关输出格式，流式问题可用 `stream: false` 对比 |
| `response_protocol` | 响应协议与配置不匹配；按实际接口选择 OpenAI Chat Completions 或 Anthropic Messages，不支持 Responses API |
| `response_shape` / `stream_shape` | 缺少必要字段或字段类型不正确；需要接口返回与所选协议兼容的数据 |
| `upstream_error` | 接口在 HTTP 200 正文中返回错误；由维护者查看网关日志，确认模型权限、参数或工具调用支持 |
| `tool_shape` / `tool_arguments` | 工具调用缺少必要字段，或参数不是 JSON 对象；本轮不会执行这些无效调用 |

程序不会自动换协议或重发模型请求。已经收到的文字仍保存在会话里，但不能将中断的内容视为完整排查结论；修正配置或更新程序后可在原会话继续。若仍有问题，提供诊断码、`provider`、`stream` 和接口协议即可，无需提供 API Key。

### 时间和上下文预算

| 配置 | 默认 | 允许范围 | 含义 |
|---|---:|---:|---|
| `timeout_seconds` | 120 | 5～600 | 单次模型请求的超时/流式时长预算 |
| `max_output_tokens` | 4096 | 正整数；实际上限由模型接口决定 | 每次模型返回的输出预算，例如 65536 |
| `max_context_chars` | 100000 | 20000～500000 | 发送给模型的文本上下文字符预算，不是精确 token 数 |

v2.5.1 起不再将 `max_output_tokens` 限制为 256～16000。可填写 `65536` 等正整数；原值发送给网关，是否支持取决于所选模型。它是输出上限，不要求模型每次写满。响应接收预算也随此配置增加，避免长流式回答因旧版固定 2 MB 限制提前中断；请求超时仍由 `timeout_seconds` 独立控制。修改本机 JSON 后，下一次发送即使用新值，不覆盖已有会话记录。

v2.5.3 起取消工具排查轮数的硬上限。模型还需要查询时会继续调用工具，直到给出回答、用户点击“停止排查”或发生接口/查询流程错误。旧配置中的 `max_tool_rounds` 不再生效，保留或删除都可以，无需重建日志索引。`timeout_seconds` 仍约束每次模型请求，并非整个排查任务的总时长；单次输出预算与上下文预算也仍有效。同一轮重复查询仍会被拦截并提醒模型复用结果。

超出上下文预算时优先省略较早轮次的大段工具结果，尽量保留原问题与结论；仍超限才省略较早整轮历史。界面和模型都会收到省略提示，完整本地历史不会因此删除。检索结果分页、每次传输量受限，截断会标注，不等于日志不存在。模型速度和额度由你配置的服务决定，直接 API 不承诺“所有排查秒出结果”。

## 同事使用

1. 选择日志包 → AI 排查 → 输入问题。
2. 默认勾选“发送前预览任务”：看到完整规则、查询工具定义、日志范围、代码版本后再确认。可关闭该选项直接发送；项目仍固定版本。
3. 回答期间展开查询卡片，看条件、耗时、总命中量和返回证据。点击“日志 #ID”回到原文件上下文。
4. 在当前会话输入追问并点击“继续当前对话”，不需要 Session ID。请求会携带之前的问题、回答和查询结果；多会话可切换，点击“新建”才开始另一段对话。刷新和关闭网页不会取消后端任务。
5. “停止排查”会中断模型连接，并阻止后续工具调用；已经运行的本机只读查询可能需等其返回。停止不删除历史。已发送的模型请求可能仍计费。
6. “导出报告”下载最近一次完整回答对应的报告，全部历史仍在会话中。失败时保留部分回复和证据，可以继续问“请继续上一轮排查”。
7. 删除会话需先停止；会永久删除对应聊天、工具记录和报告，不会删除日志包或项目。

所有会话对组内访问者可见、可删除。这是用户选择的可信小组共享模式，不是多租户服务。

### 多轮对话与中断后继续

v2.5.3 修复会话列表或历史加载临时失败时意外丢失当前会话选择的问题。历史尚未恢复时，页面保留会话与草稿，暂停发送并提供“重新加载会话”，避免把追问发成新任务。追问预览会明确提示正在继续当前对话；其中展示本轮任务范围，不重复展开整段聊天历史。

解析错误、手动停止或服务重启后，已保存的部分回复会在下一次追问时作为带“中断/未完成”标记的普通文字带给模型，方便理解“继续刚才”的指代；不会恢复或执行未验证的工具调用。此前完成的工具结果仍作为查询证据保留。此处理也适用于旧版本已保存的中断会话。

现有会话沿用创建时的日志包；切换左侧日志包不会替换该会话的历史。分析另一份日志时新建会话。项目版本可在同一会话主动更新，更新会明确标识，旧代码证据不会被当作新版本证据。

### 修改分析规则

点击“编辑分析规则”维护分析流程、公司业务规则和修改说明。保存会生成新版本；可载入历史版本或恢复默认后再保存，旧版本仍保留在 `data/analysis-rules.json`。新会话使用保存后的规则，已有会话保留创建时的规则快照；需要采用新规则时新建会话。解析字段有误时仍需修改解析器并重新导入，提示词不能修复已生成的索引。

## 结合项目代码

v2.5 改为填写 **Git 仓库 URL**，或从列表选择已经导入的仓库。代码下载到运行 LogScope 的服务电脑，不是访问网页的同事电脑；无需填写 `D:\...` 这样的本地项目路径。

1. 点击 AI 排查顶部的“关联项目代码”按钮，直接展开并启用代码分析；关联后按钮会显示当前分支。
2. 在“Git 仓库地址”填写 URL，或从“已有仓库”选择项目并回填地址。刷新仓库列表只读取本地记录，不执行远程更新。
3. 点击“更新代码 / 拉取分支”。首次使用该 URL 时，LogScope 通过 `git clone --no-checkout` 下载到 `data/projects/<仓库名-hash>/`；已有同一 URL 时复用目录并执行 `git fetch`。更新失败会明确报错，不把旧缓存当作更新成功。
4. 从“远程分支”选择要分析的版本。选择分支不会自动拉取代码；需要新提交时，再次点击更新按钮并重新选择。
5. 发送前预览仓库、分支和固定 commit。AI 从该 commit 搜索和读取代码；其他人更新同一仓库不会改变已有会话的分析版本。要让当前会话使用新版本，需要重新选择并预览确认。

也可以填写或选择仓库后直接发送问题：**新任务首次发送时，若当前尚未同步，页面会自动 clone/fetch，并默认选择远程默认分支**。想先指定其他分支时，按上面的步骤提前点击“更新代码 / 拉取分支”；发送前核对预览中的分支和 commit。仅选择仓库列表本身不触发网络。已有会话继续使用固定 commit，需主动更新并再次预览才换版本。

以下是地址形式示例，需替换为公司实际仓库：

```text
http://git.example.internal/team/FMEMateService.git
https://git.example.internal/team/FMEMateService.git
ssh://git@git.example.internal:2222/team/FMEMateService.git
git@git.example.internal:team/FMEMateService.git
```

服务电脑必须已安装可运行的 Git，且能访问公司仓库网络。鉴权使用服务电脑上配置好的 Git 凭据或 SSH 密钥；不要在 URL 中写密码或 token。HTTP(S) 地址不接受内嵌用户名或密码，SSH 地址可以包含普通用户名（例如 `git@`）。网页不会弹出 Git 登录窗口，需要登录、SSH 主机确认或补充凭据时，先在服务电脑完成设置。HTTP、HTTPS、SSH 是否可用取决于实际仓库和本机配置，以上示例不代表已对公司的各协议逐一实网验证。

Git 下载由本机 Git 执行，使用其网络与凭据配置；这与模型 API 的固定直连方式相互独立。不执行 `git pull`、checkout、构建、测试或业务代码，选择分支不会切换或覆盖工作区。克隆使用 `--no-checkout`，因此缓存目录中可能看不到展开的源码文件，AI 通过 Git 对象读取固定版本，这是正常现象。

`data/` 默认位于 EXE 或源码服务目录旁，使用 `--data` 时改为指定目录。所有同事共用其中的仓库缓存；删除日志包、删除 AI 会话及 72 小时日志包自动清理都不会删除代码。缓存仍占用磁盘空间，保留它才能继续读取引用该仓库的历史代码证据。

升级前创建的原生 AI 会话继续保留原 `project_root`、分支和 commit，仍可读取原目录；不会自动复制到 `data/projects/`。请保留原目录，或在会话中明确选择新导入的仓库并预览确认后再使用。配置文件的 `default_project_path` 仅为兼容保留，新页面不再读取它作为项目入口。

**请选择产生日志时实际部署的代码版本。** 最新远程分支不一定匹配历史日志。报告保留分支与 commit，不将“相关代码”自动等同于根因。脱敏类名/接口与真实代码不匹配时仍可能搜不到，需要补充线索。

## 组内共享启动

默认仍只监听本机。需要同事访问时：

```powershell
.\LogScope.exe --host 0.0.0.0
# 或源码
python app.py --host 0.0.0.0
```

同事访问 `http://服务电脑IP:8765`，按需允许 Windows 防火墙的专用网络入站。如果多网卡导致 Host 不受信任，可显式指定 IP：

```powershell
.\LogScope.exe --host 0.0.0.0 --allowed-host 192.168.1.100
```

无账号、无会话隔离；不要做公网端口转发。模型地址/密钥仅在维护者本机 JSON 中，浏览器访问者通过原生对话共用这份配置。

## 保存位置和升级

- `data/ai-config.json`：模型配置，含密钥，仅维护者修改。
- `data/chat.sqlite3`：原生对话、工具记录、任务和规则快照；状态增量轮询，不重放终端输出。
- `data/chat-sessions/<id>/task.md`：最近一次实际发送任务；`report.md`：最近完整报告。
- `data/projects/<仓库名-hash>/`：通过 Git URL 下载的共享代码仓库缓存，不随 ZIP、索引或 AI 会话删除。
- `data/projects/repositories.json`：已导入仓库的持久清单，用于重启后显示列表；与代码缓存一同保留。
- `data/terminal-sessions/` 和 `data/terminal-config.json`：升级时保留的旧 CLI 历史与配置，不自动删除。v2.4 不再加载或管理旧终端；可在磁盘直接打开旧任务、终端记录和报告，不自动转换成原生会话。

升级到 v2.5 请先关闭旧服务，再替换 EXE 或更新源码，完整保留原 `data` 及数据库伴随文件。**未过期的日志无需重新导入，原生 AI 会话历史不变**；旧会话引用的本地项目目录也要保留，不会自动迁移。旧 `/api/terminal/*` 接口和启动入口已移除。首次使用原生对话时再配置模型 JSON。

日志包默认在满 72 小时后的凌晨 02:00 清理 **原 ZIP 和索引**，AI 历史、配置和代码仓库保留。历史对话仍可阅读，但已删除日志的详情、原包核验和继续查询不可用；需要再次分析时，用自己留存的 ZIP 或重新采集的包导入后新建会话。保留 ZIP 列表中的原包也可手动删除，详见 [日志保留与自动清理](RETENTION.md)。

## 验证范围

自动化使用本机模拟模型服务验证：流式/非流式、工具调用、日志/代码检索、停止、断线、重复提交、预览冲突、持久化、删除以及密钥不回显。不调用真实外部模型、不发送公司日志。公司的真实网关协议和模型定位质量，需配置后实测。
