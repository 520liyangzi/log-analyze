# 原生 AI 对话排查（v2.0）

不需要启动 Claude、codeagent、CMD 或安装 Skill。LogScope 后端通过模型 API 的工具调用，执行本机日志索引查询、原包核验和固定 Git commit 的代码搜索；浏览器显示对话和可展开的查询证据。旧版终端保留独立入口与原数据。

## 维护者配置模型

1. 首次启动 `LogScope.exe` 或 `python app.py` 后，自动生成 `data/ai-config.json`。使用 `--data` 时就在指定的数据目录中。
2. 用文本编辑器打开 JSON，填写下面三个值，不要把真实密钥提交到 Git，也不要发给同事。

```json
{
  "provider": "openai",
  "base_url": "https://your-model-gateway.example/v1",
  "api_key": "你的密钥",
  "model": "接口要求的模型名"
}
```

其他字段可保留自动生成的默认值；完整示例见根目录 `ai-config.example.json`。JSON 不支持注释，Windows 路径的反斜杠要写成 `\\`，或者使用 `D:/project/mate/FMEMateService`。

3. 保存文件。页面点击“刷新状态”，下一次发送使用新配置，不需重启；已运行的一轮仍使用启动时的配置。
4. 导入演示日志包，问“请检查 /api/model/map 的报错原因”，确认出现“搜索日志索引”等工具记录，再得到回答。

页面/API 只返回是否已配置、提示文字和默认项目目录；不返回模型地址或密钥，不提供浏览器编辑入口。所有同事共用维护者配置的模型额度，当前无账号和会话隔离。

### 支持的接口

- `provider: "openai"`：OpenAI-compatible Chat Completions。`base_url` 填含 `/v1` 的前缀，程序追加 `/chat/completions`；也支持直接填写完整 `/chat/completions` 地址。使用 `Authorization: Bearer ...`。
- `provider: "anthropic"`：Anthropic Messages 格式。前缀含 `/v1`，程序追加 `/messages`；使用 `x-api-key`。不能仅因模型叫 Claude 就选此项，应以网关真实协议为准。
- 默认 `stream: true`，模型分段输出时页面持续更新。公司网关不支持流式时改成 `false`，界面保留等待状态，收到完整回复后展示。
- `openai_token_parameter` 默认 `max_tokens`。如网关/模型要求 `max_completion_tokens`，将该字段改成此值。
- 排查模型需支持结构化 `tools/tool_calls`（或 Anthropic `tool_use`）。网关拒绝该能力时会报错；若模型只回复文字而未调用工具，页面会明确提示“未新增工具查询”，不能将文字回复视为实际核查。
- 这是直接 HTTP(S) 连接，当前不自动读取系统代理，也不支持其他厂商的专有鉴权/Responses 协议。企业自签证书需在服务电脑安装信任链，不通过关闭 TLS 校验解决。
- 不使用 CLI 登录凭据，也不会自动从 Claude / 公司 Agent 提取 Key。

### 时间和上下文预算

| 配置 | 默认 | 含义 |
|---|---:|---|
| `timeout_seconds` | 120 | 单次模型请求的超时/流式时长预算 |
| `max_output_tokens` | 4096 | 每次模型返回的输出预算 |
| `max_tool_rounds` | 8 | 每次用户发言最多执行 8 轮工具，再要求模型总结 |
| `max_context_chars` | 100000 | 发送给模型的文本上下文字符预算，不是精确 token 数 |

超出上下文预算时优先省略较早轮次，必要时省略旧工具结果；界面明确提示，完整历史不会因此删除。检索结果分页、每次传输量受限，截断会标注，不等于日志不存在。模型速度和额度由你配置的服务决定，直接 API 不承诺“所有排查秒出结果”。

## 同事使用

1. 选择日志包 → AI 排查 → 输入问题。
2. 默认勾选“发送前预览任务”：看到完整规则、查询工具定义、日志范围、代码版本后再确认。可关闭该选项直接发送；项目仍固定版本。
3. 回答期间展开查询卡片，看条件、耗时、总命中量和返回证据。点击“日志 #ID”回到原文件上下文。
4. 直接追问，不需要 Session ID。多会话可切换；刷新和关闭网页不会取消后端任务。
5. “停止排查”会中断模型连接，并阻止后续工具调用；已经运行的本机只读查询可能需等其返回。停止不删除历史。已发送的模型请求可能仍计费。
6. “导出报告”下载最近一次完整回答对应的报告，全部历史仍在会话中。失败时保留部分回复和证据，可以继续问“请继续上一轮排查”。
7. 删除会话需先停止；会永久删除对应聊天、工具记录和报告，不会删除日志包或项目。

所有会话对组内访问者可见、可删除。这是用户选择的可信小组共享模式，不是多租户服务。

## 结合项目代码

默认目录是服务电脑上的 `D:\project\mate\FMEMateService`，同事电脑不需要有这个目录。可在 JSON 中修改 `default_project_path`，页面也可选其他服务端 Git 项目。

1. 打开“项目代码”，勾选“结合项目代码分析”。
2. 填项目目录。已有仓库的“远程仓库地址”可留空，使用其 `origin`；不存在的新目录需填地址，程序以 `git clone --no-checkout` 获取 Git 对象，不展开一份工作区。
3. 点击“同步并读取分支”。执行 `git fetch --no-tags origin`，默认优先选择 `origin/当前分支`；选择其他分支后再发送。如果未手动同步，首次发送时自动同步并默认选分支，请通过预览确认。
4. 预览固定 commit。后续其他人同步代码，不改变已创建会话的分析版本；同一会话手动重新同步并预览后才能换版本。目录有未提交代码也不会被覆盖。

不执行 `git pull`、checkout、构建、测试和业务代码，不修改已有 `origin`。Git 鉴权使用服务电脑已配置的 SSH/Git 凭据；禁用交互登录弹窗，凭据不可用就明确报同步失败，不偷偷用旧版本。

**请选择产生日志时实际部署的代码版本。** 最新远程分支不一定匹配历史日志。报告保留分支与 commit，不将“相关代码”自动等同于根因。脱敏类名/接口与真实代码不匹配时仍可能搜不到，需要补充线索。

## 组内共享启动

默认仍只监听本机。需要同事访问时：

```powershell
.\LogScope.exe --host 0.0.0.0
# 或源码
python app.py --host 0.0.0.0
```

同事访问 `http://服务电脑IP:8765`，按需允许 Windows 防火墙的专用网络入站。如果多网卡导致 Host 不受信任，可显式指定 IP：

```powershell
.\LogScope.exe --host 0.0.0.0 --allowed-host 192.168.1.100
```

无账号、无会话隔离；不要做公网端口转发。模型地址/密钥仅在维护者本机 JSON 中。旧 CMD API 仅接受服务电脑回环连接，组内网页用原生对话。不要通过反向代理把旧终端端点暴露出去。

## 保存位置和升级

- `data/ai-config.json`：模型配置，含密钥，仅维护者修改。
- `data/chat.sqlite3`：原生对话、工具记录、任务和规则快照；状态增量轮询，不重放终端输出。
- `data/chat-sessions/<id>/task.md`：最近一次实际发送任务；`report.md`：最近完整报告。
- `data/terminal-sessions/`：旧 CLI 会话保留。原生会话与旧 CLI 会话不互相覆盖，也不自动转换外部模型的隐藏上下文。

v2.0 不改动日志索引格式，**不需要重新导入日志**。替换 EXE/更新源码后保留原 `data`，启动并配置 JSON 即可。

## 验证范围

自动化使用本机模拟模型服务验证：流式/非流式、工具调用、日志/代码检索、停止、断线、重复提交、预览冲突、持久化、删除以及密钥不回显。不调用真实外部模型、不发送公司日志。公司的真实网关协议和模型定位质量，需配置后实测。
