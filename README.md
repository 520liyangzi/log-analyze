# LogScope · 本地多节点日志分析

上传外层 ZIP，或者调用本机采集脚本下载，先预览并确认目录和文件，再搜索全部节点的文本日志。支持不同服务使用不同目录，通过接口、Pod、时间、线程和流水号定位请求。中文界面，日志与索引保存在本机。

**Python 3.10+ 即可运行搜索和原生 AI 对话，无需额外的 AI 命令行工具、Node.js、Java、Docker 或外部数据库。** 搜索和索引可断网运行；原生 AI 使用维护者在 `data/ai-config.json` 配置的模型 API，界面不显示地址或 API Key。

## 1. Windows 启动

### 推荐：直接使用 EXE

从独立的 [`exe` 分支](https://github.com/520liyangzi/log-analyze/tree/exe)或 [Windows 最新版发布页](https://github.com/520liyangzi/log-analyze/releases/tag/windows-latest) 下载 `LogScope.exe`。把它放到固定目录后双击，程序会自动打开浏览器；日志索引、原始 ZIP、规则和 AI 会话保存在 EXE 同目录的 `data/`，以后只替换 EXE 不会覆盖这些数据。

`LogScope.exe` 已内置网页、提示词、日志查询和代码查询工具，搜索及 AI 排查不需要另装 Python。首次启动可能被 Windows SmartScreen 提示，因为当前 EXE 没有商业代码签名；可以用发布页同时提供的 `LogScope.exe.sha256` 核对文件。

在线采集是一个例外：`collect_logs.py` 是你的私有外部脚本，且它依赖什么第三方包目前无法从仓库得知，因此使用在线采集时仍需把脚本放在 EXE 同目录，并保留它原本可用的 Python 与依赖环境。上传 ZIP、搜索、流水号、删除日志包和 AI 排查不受此限制。

结合项目代码分析时，服务电脑还需安装 Git，并能访问对应仓库；同事只需浏览器，不必各自安装 Git 或下载项目。

每次 `main` 分支更新后，GitHub 会在 Windows 上自动测试源码、构建单文件 EXE、真正启动并访问首页，全部通过后覆盖发布页里的最新版，并把成品同步到独立的 `exe` 分支。`main` 只保留源码，每个构建也会作为该次工作流的 Artifact 保留。

### 使用源码

先安装 **Python 3.10 或更新版本**，安装时勾选 `Add python.exe to PATH`。已有 Python 可运行 `python --version` 检查。

```powershell
git clone https://github.com/520liyangzi/log-analyze.git
cd log-analyze
python -m pip install -r requirements.txt
python app.py
```

打开 **http://127.0.0.1:8765**。也可以双击仓库根目录的 **start.bat**，然后打开上述地址。窗口要保持运行，关闭窗口就会停止服务。

页面会保留上次选择的日志包、所在页面、搜索词、筛选条件、流水号以及 AI 问题。刷新浏览器后可继续填写；这些内容只保存在当前浏览器的本地存储中。

Linux / macOS：

```bash
git clone https://github.com/520liyangzi/log-analyze.git
cd log-analyze
python3 app.py
```

端口占用时：`python app.py --port 8877`，浏览器也改为 `http://127.0.0.1:8877`。

### v2.3：先确认目录，再导入日志

上传和在线采集都改为 **扫描目录 → 预览样例和分类 → 修改并确认 → 建立索引**。不再要求所有服务都使用 `namespace_pod/service/pod-service/log/`。可以勾选任意实际目录，修改文件名通配符、Node、命名空间、Pod、服务和日志类型；不确定的识别结果会提示需要确认。扫描与目录推断不调用大模型。

ZIP 根目录、`logs/`、其他服务目录中的文本或 GZIP 日志均可选择；非常见扩展名可手动设置匹配。可以保存方案，刷新/重启后从待确认入口继续。新流程的扫描或导入失败会暂留 ZIP，在 72 小时保留期内可修改规则或重新扫描后重试，无需重复上传。详细操作见 [目录确认导入指南](docs/IMPORT_LAYOUT.md)。

目录可调整不等于所有日志字段都能自动识别。未知格式按文本保留并可关键词搜索；时间、流水号和接口筛选仍依赖可识别的日志字段。不支持加密 ZIP、7z、rar、tar 或二进制日志。

### 夜间清理、真实进度与安全停止

默认在**每天服务电脑本地时间凌晨 02:00**，删除导入完成已满 **72 小时**的日志包：包括上传或在线采集得到的 **原始 ZIP、日志记录、索引和导入方案**，并压缩数据库释放磁盘空间。**AI 对话、配置和 `data/projects/` 代码仓库不删。** 这里节省的是磁盘空间，不是直接清空运行内存。

左侧“查看保留 ZIP”可查看尚存归档、下载或手动删除不需要的 ZIP。需要长期留存的原包应提前下载；自动清理后再次分析，需使用自行保存的 ZIP 或重新采集。72 小时从导入完成开始计算，与日志中的事件时间无关；旧包缺少该时间时用原创建时间，到期后等下一次每日清理，不会在第 72 小时强制中断任务。

**默认不再启动补扫，也不在白天自动重试。** 只有程序运行期间到达本地 02:00 才开始清理；错过则等下一次 02:00。有导入、查询或 AI 任务时，仅在 02:00～03:00 窗口内每 15 分钟重试。页面显示真实阶段、耗时和已处理包数；SQLite 单条删除/压缩没有可用百分比，使用不确定进度条。可点击“停止本次清理”，等待 SQL 中断或事务回滚完成，页面不会提前宣称已恢复。

升级请先关闭旧 LogScope，再替换 EXE 或更新源码，**完整保留原 data 及 logs.sqlite3-wal 等数据库伴随文件**。新版本默认不会一开机就清理；未被清理的日志无需重新导入。v2.5 默认采用 ZIP 与索引一起删除的策略，旧版留下的原包也按原时间过期；已经完成的删除不能靠升级或取消撤销。

可在自动生成的 `data/retention-config.json` 设置 `enabled`（默认 `true`）、`startup_catchup`（默认 `false`）和 `max_run_seconds`（默认 `300`），修改后重启生效。运行时长是发出安全停止请求的预算，不是包含事务回滚在内的硬截止时间；一般保留默认值即可。

未完成导入的待确认或失败包，按原创建时间超过 72 小时清理原 ZIP、方案和残留索引。清理仅管理 LogScope 数据目录中的日志包，不扫描采集脚本任意输出路径或电脑上的其他下载文件。

页面“删除当前日志包”可立即删除指定包的 ZIP 与索引，不必等待过期；“查看保留 ZIP”支持手动删除剩余归档。完整说明见 [日志保留与自动清理](docs/RETENTION.md)。

## 在线采集日志

把你已有的 `collect_logs.py` 放到 `app.py` 同级目录。该文件已加入 `.gitignore`，不会被误提交到仓库。启动 LogScope 后点击 **在线采集日志**，填写 Pod 关键字和时间范围：

```powershell
python collect_logs.py --pod xxxx --start "2026-09-10 14:00:00" --end "2026-09-10 16:30:00"
```

页面会为每次任务传入独立的 `--output` 临时目录。脚本成功后，LogScope 从目录中选择最新生成的 ZIP，校验格式并扫描目录；**确认目录方案后**才建立索引，随后切换到该日志包。点击 **环境管理** 可保存多套平台地址、用户名和密码；在线采集时选择环境会自动回填地址与用户名，并由本机服务直接使用保存的密码，密码不会回显到浏览器。环境保存在 `data/collector-environments.json`，请像保护日志和 AI 会话一样保护整个 `data/` 目录。也可以选择“手动填写本次连接”。无头模式、超时、轮询和日志解析参数仍在高级设置中。

## AI 排查：页面对话

页面直接连接配置的模型，支持多会话、日志查询和代码定位，不需要 Claude / codeagent 命令或外部 Session ID。

1. 启动后编辑自动生成的 `data/ai-config.json`，填写 `base_url`、`api_key`、`model`。完整示例见 [ai-config.example.json](ai-config.example.json)。
2. 选择日志包 → **AI 排查** → 输入问题 → 预览任务 → 确认发送。
3. 页面逐步显示回答与真实工具查询记录，可展开条件/证据、继续追问、停止、切换会话、删除和导出报告。所有对话自动保存，刷新不丢失。
4. 可选结合代码：选择已导入仓库或填写 Git URL，代码保存在服务电脑的 `data/projects/`。新任务首次发送时若尚未同步会自动 clone/fetch，默认使用远程默认分支；也可提前点“更新代码 / 拉取分支”选择其他分支。预览后固定 commit，已有会话需主动更新并再次预览才换版本，不 pull、不切换工作区。

支持 OpenAI-compatible Chat Completions 和 Anthropic Messages 格式。模型需支持工具调用；API 地址/密钥不回显到浏览器。按当前需求，组内共用配置和会话，不做登录隔离；用 `LogScope.exe --host 0.0.0.0` 或 `python app.py --host 0.0.0.0` 开启组内访问，不要暴露公网。

支持带端口的内网 HTTP 模型地址；模型请求由服务电脑直连，不读取系统代理环境变量。“配置无效”表示本机 JSON 校验未通过，尚未请求模型；页面会提示出错字段或 JSON 行列，不回显配置值。详细配置、使用、共享启动和网络排查见 [原生 AI 对话指南](docs/NATIVE_AI.md)。

**编辑分析规则** 可以维护通用流程和公司业务规则，支持历史版本、恢复默认及修改备注。新会话使用保存后的规则；已有会话保留自己的规则快照，需要使用新规则时新建会话。日志解析格式变化仍需修改解析器，不会因为更新提示词自动修正旧索引。

AI 通过工具查询现有 SQLite/FTS 索引，不重新解压或建立索引。整体耗时还包括模型推理、多轮查询、必要的原包核验和报告生成；可展开每次工具记录，区分查询耗时与模型等待。

### 升级到 v2.5

先关闭旧服务，再替换 EXE 或更新源码并启动，**完整保留原 `data/` 与 SQLite 伴随文件**。未被清理的日志无需重新导入；原生 AI 的会话、工具记录和报告继续使用。EXE 发布到独立的 `exe` 分支和 Release，`main` 保持源码。

## 3. 上传真实日志包

以下是可自动识别的一种常用目录，**不是 v2.3 的强制目录结构**：

```text
任意外层.zip
├── fileList.txt
├── 任意node-a.zip
│   └── namespace_pod/
│       └── service/
│           └── pod-service/
│               └── log/
│                   ├── access.log
│                   ├── root.log
│                   ├── run.log
│                   └── root.2026-09-08.log.gz
└── 任意node-b.zip
    └── ...
```

程序实际遍历 ZIP 内容，不依赖 `fileList.txt` 的准确性。清单文件默认不参与检索；目录预览会显示其他目录、文件和样例，你可以重新选择并调整匹配规则。内层 ZIP 文件名通常作为 Node 的初始推测，可以修改分类，但真实归档链与文件路径始终保留。内层 ZIP 会流式写入临时文件，以读取目录；GZIP 以流方式读取。扫描仅取有限样例，不建立全文索引；确认导入时才读取选中日志全文。外层 ZIP 保留供「核验原始压缩包」回读，旧版未保留原 ZIP 的包需重新上传才可核验。

左侧会显示当前原始 ZIP 的大小。搜索结束后点击 **删除当前日志包**，确认后会快速删除该包的索引和原始 ZIP；如需让 SQLite 文件立即缩小，可在确认框中额外选择整理数据库。正在被 AI 排查使用的日志包需要先停止对应会话；历史对话和已经生成的报告继续保留。

时间筛选可以直接粘贴日志中的 `2026-09-08 15:15:30.243`，也兼容 `2026-09-08T15:15:30.243`、斜杠日期、方括号和 `+0800` / `+08:00` 时区。不填写时区就使用旁边选中的筛选时区。

导入选项：

- **编码**：默认先按 UTF-8 逐行解码，失败回退 GB18030；已知编码可明确指定 UTF-8 / GB18030（兼容 GBK）。无法解码的字符会显示替换符，并给出导入提示。
- **无时区日志**：默认 `+0800`，有显式时区的 root 日志优先使用它自己的时区。
- **access 最后一列**：新版说明明确为耗时，默认毫秒；兼容其他包时可改秒或微秒；界面统一显示 ms，原始文本完整保留。若该字段在你们系统里不是耗时，需要据真实字段定义调整解析器。

## 4. 搜索怎么用

| 需求 | 操作 |
|---|---|
| 全节点搜接口、关键字、时间字符串 | 输入搜索框，不选 Node / Pod / 类型 |
| 只搜一个节点 | 选 Node |
| 只搜一个 Pod | 选 Pod；选项包含 namespace，避免同名混淆 |
| 只搜 access / root / interface 等 | 选日志类型，类型从实际文件名生成 |
| Pod 与类型叠加 | 同时选择两个筛选 |
| 指定文件名 | 填 `root*.log*`、`access.log`；使用 SQLite GLOB，支持 `*`、`?`、`[]`，区分大小写 |
| 精确打开来源文件 | 文件目录点击「搜索此文件」，内部按文件 ID 限定，避免同名文件串搜 |
| 查 HTTP 错误 / 慢请求 | 更多筛选填 `500` / `5xx` / 最低耗时 ms |
| 根据 access 查正式日志 | 点击「同 Pod 相邻日志」，自动清空接口搜索词，保留所有日志类型，按含 access 耗时的时间范围检索 |
| 查一个请求 | 进入流水号追踪，完整 ID 精确匹配；64 位以上数字也按字符串处理 |
| 看异常堆栈 | 每条记录保留后续多行；搜索到堆栈内容时展示整条记录 |
| 原文核验 | 点击「核验原始压缩包」，回读原 ZIP 中对应文件/行并与索引原文比较 |
| 回到原文件查看前后内容 | 点击「查看上下文」，展示原文件相邻记录和原始行号 |
| 保存全部结果 | 点击「导出全部」，下载 NDJSON，每行 JSON 包含原文、行号和完整来源 |

所有搜索条件是 **AND** 关系；主搜索框是连续文本匹配（默认忽略英文大小写），不是正则、分词或多关键词 OR。空关键词可以浏览整个已选范围。分页每页 50 条，可跳页，**没有只保留前 N 条的截断**。总数是日志记录数，堆栈合并后的一条记录可以包含多行原始文本。

时间筛选包含起止边界，默认按 UTC+08:00 输入，也可选 UTC。界面会保留每条日志解析时采用的时区。时间排序基于实际时间戳；没有识别到时间的记录排在最后。节点时钟偏差不做自动校正。

SQLite 支持 FTS5 trigram 时自动使用连续子串索引，再检查原文；不支持时自动降级扫描，功能仍然可用，速度受日志规模影响。索引会占用额外磁盘；首次导入需要时间，后续不需要重新解压。

## 5. 流水号与关联的边界

root 按下面格式提取第一、第二个 ID，第一列 ID 作为流水号，第二列也是重复的 traceId；旧 API 字段名 `span` 仅兼容保留，不代表父子 Span：

```text
[2026-09-08 09:29:02.186 +0800] [9124859898865451127] [9124859898865451127] [INFO] [http-nio-uds-exec-9] [aaaaservice.java] [com.xxxx] [Map] [125] Successfully loaded model map,count: 5
```

access 格式支持普通双引号和反斜杠转义双引号：

```text
2026-09-08 09:55:14,158 INFO  162 [http-nio-uds-exec-7][ROOT][][c.h.c.t.a.l.AccessLogValveExt 28] \"GET /api/model/map HTTP/1.1\" 200 14 - 3
```

流水号页面只纳入被解析为同一完整流水号的记录。其他格式里仅仅出现某个 ID，可以用全局关键词搜索；暂不猜测所有可能的 ID 字段。时间线不假装知道父子服务调用关系。access 若没有流水号，使用同 Pod、时间窗口和可选线程查候选日志；HTTP 200 也可能对应 root/rest 的业务 WARN/ERROR；RouteID、RequestId 与 traceId 是不同字段。**线程复用、异步线程切换都可能造成误匹配或漏匹配**，因此同线程筛选默认不开启。

## 6. 数据、限制与维护

默认只监听 `127.0.0.1`。可用 `--host 0.0.0.0` 开启可信组内共享，无登录或会话隔离，不适合公网。Host / Origin 校验保留。无第三方 CDN 或前端遥测。原生 AI 会将命中的日志/代码片段发送到配置的模型服务，请使用公司允许的接口。

- 数据位置：`data/logs.sqlite3` 及 SQLite 伴随文件；重启保留导入记录。原 ZIP 位于 `data/archives/`，因此会额外占用压缩包大小的磁盘空间。压缩包显示的 50 MB 不是解压后日志大小；数据库还要保存每条记录的解析字段与三元全文检索结构，因此一定会大于原 ZIP。v1.14 已避免索引再次复制整段原文并移除词位明细，同时将导入缓存和 WAL 控制在固定范围内。
- 自动清理：导入完成满 72 小时的原始 ZIP、日志记录、解析元数据、检索索引及导入方案，在程序运行期间的服务电脑本地 02:00 清理；默认错过不补扫、不在白天重试。AI 会话、配置和项目代码保留；数据库压缩后实际归还磁盘空间。页面显示真实阶段，可请求安全停止，但已删除的数据不恢复。详情见 [自动清理说明](docs/RETENTION.md)。
- 删除某个日志包只会删除该包的原 ZIP、日志记录和索引，不会删除整个 `data/` 目录。`logs.sqlite3` 仍是应用数据库容器，目录中还可能有 AI 会话、分析规则、模型配置和采集工作目录；即使没有日志包，这些文件或目录也会保留。
- 分析规则：`data/analysis-rules.json` 保存本机自定义流程、业务规则及全部历史版本。`data/collector-environments.json` 保存采集环境及密码。
- 原生 AI：`data/ai-config.json` 保存共享模型配置（含密钥，不回显）；`data/chat.sqlite3` 保存会话和工具证据；`data/chat-sessions/<id>/` 保存任务与最新报告。组内会话共享，不做用户隔离。
- 项目代码：通过 Git URL 导入到服务电脑的 `data/projects/<仓库名-hash>/`，同一 URL 复用，组内共享。选择分支不会 checkout；已有仓更新使用 fetch，AI 从固定 commit 读取。日志包手动或自动删除、会话删除均不清理代码缓存。
- 旧终端历史：升级前已有的 `data/terminal-sessions/<id>/` 和终端配置仅保留在磁盘；v2.4 不再加载、启动或管理这些会话。确认不再需要后可自行备份或清理，不要删除仍在使用的原生 AI 数据。
- 大日志包会同时占用保存的原始 ZIP 与 SQLite/FTS 索引空间。导入采用流式读取，v1.4 减少了每条记录一次多余的数据库写入；实际耗时仍取决于压缩后大小、解压后行数和磁盘速度。
- 更换目录：`python app.py --data D:\logscope-data`。
- 清空数据：先停止服务，再删除自己的 `data` 目录。
- ZIP 导入失败时整体回滚，显示明确错误，不把不完整结果冒充成功。
- 导入方案保存在 `data/import-plans/<日志包ID>.json`，可保存已确认的目录、文件匹配、分类和解析选项；扫描/导入失败的新 ZIP 暂留在 `data/archives/` 供重试，仍受 72 小时保留期约束。手动删除或自动过期均会清理该包的方案和原包。
- 暂不支持加密 ZIP、7z、rar、tar 和二进制日志；目录层级可自定义，未识别的日志头仍保留原文供搜索。
- 没有毫秒/时间头的续行附在前一条日志后，避免拆散 Java 异常堆栈。
- 超大日志暂未做分布式搜索；导入串行执行。无关键词全量统计、导出和大量匹配时会较慢。

可通过环境变量调整资源上限（默认值如下）：

| 环境变量 | 默认 | 含义 |
|---|---:|---|
| `LOG_MAX_UPLOAD_GB` | 4 | 外层 ZIP 大小上限 |
| `LOG_MAX_EXPANDED_GB` | 20 | 累计读取的嵌套 ZIP 字节及日志解压字节上限，保守合计 |
| `LOG_MAX_RECORD_MB` | 8 | 单行或合并多行记录上限，超过则导入报错，不静默截断 |

嵌套深度最多 4 层，ZIP 条目最多 100000。数据、压缩包、密钥和本地配置均已列入 `.gitignore`，请不要强制提交真实日志。

## 7. 开发与验证

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m py_compile app.py analysis_rules.py demo.py chat_engine.py ai_client.py chat_projects.py project_access.py skills/logscope/scripts/project.py
```

可选安装 Node.js 后执行 `node --check dist/app.js` 检查前端语法；**运行项目不需要 Node.js**。

```powershell
.\build_exe.ps1
```

生成文件位于 `release\LogScope.exe`。

目录：

